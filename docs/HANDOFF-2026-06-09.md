## CORRECTION (later same day) — the "LLVM recipe" was WRONG; read this first

Verified against the **installed Bootsharp 0.9.0-alpha.30 package source**
(`~/.nuget/packages/bootsharp/0.9.0-alpha.30/build/`), not docs:

- The LLVM switch is internal **`BsLlvm = !$(BsDebug)`** → **TRUE automatically in
  any `-c Release` build.** `BootsharpLLVM` is NOT a real property — inventing it +
  `RestoreAdditionalProjectSources` to the dnceng-experimental feed was a fabricated
  recipe. The docs ("Release auto-enables NativeAOT-LLVM") were RIGHT.
- `Bootsharp.props` already sets, under `$(BsLlvm)`: `DotNetJsApi`, `EmccFlags -O3`,
  `UsingBrowserRuntimeWorkload=false`, `PublishTrimmed`, `DebugType=none`. Nothing to
  hand-add.
- The ILCompiler.LLVM toolchain is **BUNDLED in the package** at
  `$(BsLlvmDir) = $(BsRoot)/llvm` (`microsoft.dotnet.ilcompiler.llvm/` +
  `runtime.win-x64...` etc., confirmed present). `Bootsharp.targets` imports it when
  `$(BsLlvm)`. **Do NOT add a `PackageReference Microsoft.DotNet.ILCompiler.LLVM` from
  the experimental feed** — a second, differently-versioned ILC COLLIDES with the
  bundled one.
- **`global.json` stays at 10.0.204 / `allowPrerelease:false`.** The bundled ILC is a
  nuget package inside Bootsharp, not an SDK feature — no experimental SDK needed.
- ⇒ `Motely.Wasm.csproj` recipe block was reverted to just the 4 Bootsharp/DI
  `PackageReference`s. **A Mono dist (the `addRunDependency` crash) means the failing
  build was Debug (`BsLlvm` false), not that LLVM needs wiring.** Fix = build `-c Release`.
- **Discriminating check BEFORE boot test:** in the publish log, if it resolved
  `Microsoft.NETCore.App.Runtime.Mono.browser-wasm` → still Mono, Release wasn't the
  fix (next suspect: emscripten env-var / wasm-workload shadowing ILC). If it ran
  ILC + emcc/wasm-opt → NativeAOT-LLVM, the right loader.

## Bootsharp build — the god-tier findings (write these down, they cost a day)

- **Embed switch is `BootsharpBinariesDirectory`, NOT `BootsharpEmbedBinaries`.**
  From #216 source: `<BsEmbed>$([System.String]::IsNullOrEmpty('$(BootsharpBinariesDirectory)'))</BsEmbed>`
  → **empty = embedded base64** (single-file, for CDN script tag), **set =
  sideloaded** (separate `.wasm`). `BootsharpEmbedBinaries` does not exist in this
  version; the bootsharp.com docs are for a different release.
- **Local alpha feeds** (user-level `%APPDATA%/NuGet/NuGet.Config`):
  `bootsharp-local` = `D:\bootsharp\src\cs\.nuget`,
  `bootsharp-filesystem` = `D:\extra\bootsharp\cs\.nuget`. `0.8.1-alpha.3` is
  **elringus's** (via `d:/bootsharp`), not a ghost.
- **Version = MinVer** (git tag `v0.8.0` + commit height → `0.9.0-alpha.30`).
- **To rebuild the alpha:** `dotnet pack` Bootsharp.Common → Inject → Bootsharp
  (meta needs Common in the feed first) into `D:\bootsharp\src\cs\.nuget`; pack
  `d:/extra/.../Bootsharp.FileSystem.csproj` into `D:\extra\bootsharp\cs\.nuget`.
  Then bump `Directory.Packages.props` (currently `0.9.0-alpha.30` +
  FileSystem `2026.6.9.1134`).
